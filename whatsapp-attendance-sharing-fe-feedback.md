# WhatsApp Attendance Sharing — Frontend Feedback & Implementation Brief

## Objective

Improve the WhatsApp attendance-sharing format so that it is:

- easier to scan
- shorter and cleaner
- consistent across sessions
- still detailed enough to be useful
- encouraging rather than purely administrative
- generated directly from the attendance data already available in the app

This is not a request to redesign the attendance records themselves. It is specifically about improving the WhatsApp message generated by the frontend.

---

## 1. Recommended Message Structure

The WhatsApp message should follow this order:

1. Report title
2. Session name
3. Session date
4. Compact summary
5. Present members grouped by voice part
6. Apologies shown as one combined list
7. Absent count
8. Short encouraging closing paragraph

The message should remain compact because it may be shared around four times a week.

---

## 2. Compact Summary

Use only:

```text
✅ Present: 26  |  🟡 Apology: 8
```

Do not include:

- Expected members
- Participation rate
- Absent count at the top

The absent count already appears at the bottom, so repeating it in the summary would make the message feel bloated.

The app should calculate the Present and Apology totals from the same attendance data used to generate the names.

---

## 3. Present Members

Present members should be shown first.

They should be grouped by voice part:

- Soprano
- Alto
- Tenor
- Bass

Each part heading should include the number of members present in that part.

Example:

```text
*PRESENT MEMBERS*

*Soprano — 10*
Sis Anozie Rachael
Sis Chinaza Ugwuneke
Sis Chinwendu Dimobika

*Alto — 5*
Sis Egbo Janet
Sis Ogunnaike Deborah

*Tenor — 6*
Bro Abraham Zakpe
Bro Fidel Justus

*Bass — 5*
Bro Augustine Innocent
Bro Chinedu Knight
```

### Requirements

- Only members marked Present should appear in these grouped lists.
- Apologies must not be mixed into the Present lists.
- The count beside each voice part must be calculated automatically.
- Do not manually hard-code the part totals.
- Preserve the member display names stored in the database.
- Do not attempt to correct capitalization, spacing, or duplicate member records in this frontend task.

Those are data-quality concerns and should remain outside the scope of this presentation change.

---

## 4. Apology List

Do not separate apologies again into four voice-part sections.

Instead, show one combined apology list and display each member’s part beside the name.

Recommended format:

```text
*APOLOGIES — 8*

Sis Modeva Gloria — Soprano
Sis Okupevi Deborah — Alto
Sis Peter Alice — Alto
Sis Tessy Ogbodor — Alto
Sis Victoria Ejezie — Alto
Bro Nwajibia Emmanuel — Tenor
Bro Nwajibia Ugochukwu — Tenor
Bro Kalu Samuel — Bass
```

### Requirements

- Show one combined apology section.
- Include the total number of apologies in the heading.
- Show the member’s voice part beside the name.
- Prefer full part names instead of abbreviations such as `Sop`.
- Use the member’s stored title/name format as it exists in the database.

---

## 5. Absent Count

Show the absent count only once, at the bottom of the attendance list.

Example:

```text
🔴 *Absent Members: 29*
```

Do not list absent members individually in this WhatsApp format.

The detailed PDF remains the better place for full historical and detailed reporting.

---

## 6. Session Name Generation

The current session titles are manually entered and can vary, for example:

```text
Thursday rehearsal
Monday rehearsals
Rehearsal
6:30am Mass
9am Mass
Sunday Mass (7am) Mass center
```

To improve consistency, the frontend should generate the normal WhatsApp session title from the existing category, subcategory, date, and time data.

The category and subcategory already exist in the interface, so the title can be derived from them.

### Rehearsal naming

For normal rehearsals:

```text
{Day} Rehearsal
```

Examples:

```text
Monday Rehearsal
Thursday Rehearsal
Saturday Rehearsal
```

### Mass naming

For a regular Mass:

```text
{Time} Mass
```

Examples:

```text
6:30am Mass
9am Mass
```

### Mass Centre naming

For a Mass Centre session:

```text
{Time} Mass Centre
```

Example:

```text
7am Mass Centre
```

### Custom titles

Allow a manual custom title only for unusual sessions or events such as:

```text
Christmas Carol Rehearsal
Deanery Mass
Concert Sound Check
Lenten Retreat
```

For ordinary weekly sessions, the automatically generated title should be the default.

### Suggested formatter

```ts
type SessionNameInput = {
  category?: string;
  subcategory?: string;
  date: Date | string;
  startTime?: Date | string;
  customTitle?: string;
};

const getSessionDisplayName = ({
  category,
  subcategory,
  date,
  startTime,
  customTitle,
}: SessionNameInput): string => {
  if (customTitle?.trim()) {
    return customTitle.trim();
  }

  const normalizedCategory = category?.trim().toUpperCase();
  const normalizedSubcategory = subcategory?.trim().toUpperCase();

  if (normalizedCategory === 'REHEARSAL') {
    return `${format(date, 'EEEE')} Rehearsal`;
  }

  if (normalizedSubcategory === 'MASS CENTER') {
    return `${formatSessionTime(startTime)} Mass Centre`;
  }

  if (normalizedCategory === 'MASS') {
    return `${formatSessionTime(startTime)} Mass`;
  }

  return subcategory || category || 'Attendance Session';
};
```

The exact implementation can be adapted to the project’s existing date and time utilities.

## 7. Closing Paragraph

Keep a short encouraging closing paragraph at the end of every WhatsApp attendance message.

This is important because the message should not end abruptly with the absent count. The closing should acknowledge effort, encourage consistency, and make the communication feel human.

Do not use one fixed sentence every time.

Use a small logic-based pool of alternatives.

### Suggested logic

- Strong attendance: celebrate consistency
- Average attendance: encourage continued improvement
- Low attendance: encourage renewed commitment without sounding harsh
- Many apologies: appreciate responsible communication
- Default: thank everyone and encourage the next gathering

### Suggested message pool

#### General/default

```text
_Thank you to everyone who attended or communicated their absence. Let us continue to build a choir marked by commitment, consistency, and love for the music._
```

```text
_Every rehearsal strengthens the sound we create together. Thank you for showing up, and let us return even stronger at the next gathering._
```

```text
_Your presence matters, your voice matters, and your commitment strengthens the entire choir. Thank you for being part of the work._
```

#### Strong attendance

```text
_Great music is built long before the performance, one rehearsal and one committed member at a time. Thank you for contributing your part._
```

```text
_Each time we gather, we become stronger as one choir. Thank you for showing up and helping us move the music forward._
```

#### Many apologies

```text
_Thank you to everyone who was present and to those who communicated responsibly. Let us keep growing in consistency and readiness._
```

#### Lower attendance

```text
_Our strength depends on every voice taking its place. Let us make a renewed effort to be present and prepared at the next gathering._
```

### Selection approach

Do not choose from the entire pool with completely unrestricted randomness.

First select the appropriate tone group based on the session figures, then randomly choose one message from that group.

This keeps the message fresh while ensuring the tone fits the attendance situation.

## 9. Frontend Actions

The frontend should provide an easy way to use the generated message.

Recommended actions:

```text
Copy WhatsApp Message
Share to WhatsApp
```

### Copy action

- Copy the fully formatted text to the clipboard.
- Preserve WhatsApp formatting characters such as `*` and `_`.
- Show a clear success state such as `Copied`.

### Share action

Where supported, use the Web Share API or a WhatsApp share URL.

Fallback to the copy action where direct sharing is unavailable.

## 10. Suggested Data Shape

A clean formatter can receive a structure similar to:

```ts
type VoicePart = 'Soprano' | 'Alto' | 'Tenor' | 'Bass';

type AttendanceMember = {
  id: string;
  displayName: string;
  voicePart: VoicePart;
  status: 'PRESENT' | 'APOLOGY' | 'ABSENT';
};

type WhatsAppAttendanceInput = {
  category?: string;
  subcategory?: string;
  customTitle?: string;
  date: Date | string;
  startTime?: Date | string;
  members: AttendanceMember[];
};
```

The frontend formatter should derive:

- session title
- Present total
- Apology total
- Absent total
- Present members grouped by part
- count per part
- combined apology list
- closing-message tone
- final WhatsApp text

---

## 11. Formatting Rules

Use WhatsApp markdown formatting:

```text
*bold*
_italic_
```

Avoid:

- large decorative blocks
- too many emojis
- unnecessary statistics
- repeated absent totals
- participation percentages
- expected-member totals
- apology members mixed into Present lists
- separate apology subsections for every voice part
- manually typed voice-part counts

Keep the message readable on a phone screen.

---

## 12. Edge Cases

The formatter should handle the following cleanly:

### No apologies

```text
🟡 Apology: 0
```

The apology section may be omitted entirely when there are no apologies.

### Empty voice part

Do not show a voice-part section when no member from that part was present.

### No present members

Show:

```text
*PRESENT MEMBERS*

No members recorded as present.
```

### Long names

Allow names to wrap naturally. Do not truncate names in the WhatsApp text.

### Unknown voice part

Use:

```text
Other
```

or the project’s existing fallback label.

### Custom title

Use the custom title when provided; otherwise use the category/subcategory formatter.

---

## 13. Acceptance Criteria

The implementation is complete when:

- Present and Apology totals are generated automatically.
- The summary shows only Present and Apology.
- Present members are grouped by voice part.
- Each voice-part heading includes its Present count.
- Apologies appear in one combined list.
- Each apology includes the member’s voice part.
- The absent count appears only once at the bottom.
- The message ends with an encouraging closing paragraph.
- The closing message is selected from an appropriate tone group.
- Standard weekly session titles are generated from category, subcategory, date, and time.
- Custom titles remain available for unusual events.
- Stored member names are displayed as-is.
- The frontend does not attempt to fix database duplicates, capitalization, or spacing.
- The generated text preserves WhatsApp bold and italic formatting.
- The message can be copied easily.
- Direct WhatsApp sharing is available where supported.
- Empty voice parts and zero-apology sessions are handled cleanly.
- The generated message remains compact enough for frequent sharing.

---

## Scope Reminder

This task is only about the WhatsApp attendance-sharing presentation and frontend generation logic.

Do not:

- redesign the attendance database
- merge duplicate members
- correct member capitalization
- alter stored names
- change attendance calculations
- add extra report statistics
- include the full absent-member list

The goal is a cleaner, more consistent, encouraging WhatsApp message generated from the existing attendance data.
